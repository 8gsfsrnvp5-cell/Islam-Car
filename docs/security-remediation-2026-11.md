# Исправления по аудиту от 4 ноября 2026

Изменения подготовлены для существующего репозитория Islam-Car. Работающего хостинга нет;
сервер, TLS, firewall, реальная доставка SMS и реальные платежи не проверялись.

## Что исправлено

| Проблема | Изменение |
|---|---|
| Ошибка при изменении графика черновика | Старые строки удаляются до вставки новых; проверяется сумма и уникальность номеров |
| Старые сессии после смены пароля/2FA | Другие сессии отзываются; повторная активация покупателя отзывает все его сессии |
| Повторное использование TOTP | Шаг последнего кода сохраняется атомарно; повтор запрещён; ошибки настройки 2FA ограничиваются |
| Подмена IP через X-Forwarded-For | Приложение использует адрес ASGI; доверие ко всем прокси удалено из Docker |
| Обход маскирования контактов | Скрываются email, логин кабинета, заметки и контакты заявок для ролей без clients.pd |
| Обход payments.read через договор | Вложенные платежи и сообщения об оплате подчиняются тому же праву |
| Выдача полных документов всем сотрудникам | Введено documents.content: только владелец и администратор; охватывает создание, предпросмотр, чтение, экспорт и сканы |
| Отозванные шаблоны и устаревшие документы | Перед утверждением/подписанием проверяются текущий шаблон, источник данных и целостность текста; отзыв охватывает все прежние утверждения |
| Конкурирующие платежи и изменение графика | Блокировки договора/банковской операции; внешний идентификатор защищён уникальным индексом; PostgreSQL-тест двух одновременных поступлений |
| Недостаточная проверка платёжного провайдера | Проверяются идентификатор, RUB, сумма, тестовый режим и принадлежность уже учтённого платежа |
| Неполные условия подписания | Обязательны дата покупки не позднее продажи и раскрытие стоимости; режим продавца обновляется перед подписанием |
| Долгие фоновые задачи | Берётся одна задача; отдельная PostgreSQL advisory-блокировка защищает выполняющуюся задачу после истечения lease |
| Опасное восстановление копии | Разрешена только другая база с суффиксом _restore_check; проверяются реальные имена баз; архив файлов проверяется по SHA-256 и ZIP CRC |
| Формальная проверка сканов по заголовку | Проверяется структура PDF/JPEG/PNG, размер изображения; отклоняются активное содержимое и вложения PDF |
| Неограниченное тело HTTP-запроса | Лимит 24 MiB до разбора JSON/multipart, в том числе без Content-Length |
| Вопрос в ИИ без предварительной проверки | Перед внешним вызовом показывается очищенный текст; требуется подтверждение именно этого текста |
| Небезопасные настройки production | Запуск отклоняется при небезопасных cookies, отключённой обязательной 2FA, HTTP origins, тестовых каналах/платежах |

## Изменения поведения

Полные документы совмещают персональные и финансовые сведения. Поэтому менеджер, бухгалтер,
юрист, аудитор и специалист по шариату сохраняют доступ к разрешённым карточкам/реестру,
но не к полным документам. Юрист сохраняет утверждение шаблонов и аудит документов.
Это консервативное ограничение. Раздельные обезличенные версии документов можно добавить отдельно
после определения, какие поля нужны каждой роли.

Покупатель сохраняет доступ к своим разрешённым документам. Подписанные исторические документы
не переписываются при изменении карточек или шаблонов.

Новая миграция 0005 добавляет состояние TOTP, контрольные суммы архивов файлов и уникальный индекс
подтверждённых внешних платежей. Если в существующей базе уже есть дубли, миграция остановится;
автоматического удаления финансовых записей нет. До миграций необходима резервная копия.

## Подготовка сервера после выбора хостинга

1. Использовать отдельные реальные домены клиента/админки, HTTPS и ENVIRONMENT=production.
   Установить COOKIE_SECURE=true, ALLOWED_ORIGINS, CLIENT_PUBLIC_URL и PUBLIC_CLIENT_URL.
2. Пример nginx — docker/nginx.example.conf. Заменить домены и пути сертификатов;
   проверить nginx -t. Это шаблон, не установленная и не проверенная конфигурация сервера.
3. API и база остаются на внутренних портах. FORWARDED_ALLOW_IPS задаётся по фактическим адресам
   доверенного Next.js-прокси; не использовать '*'. На внешнем прокси входящие X-Forwarded-For
   заменяются. До настройки адрес может быть общим для клиентов — это ограничивает доступ,
   но не позволяет обходить лимит произвольными заголовками.
4. Миграции выполнить отдельно ролью владельца схемы. Создать runtime-роль по docker/runtime-role.sql,
   задать её DATABASE_URL и RUN_MIGRATIONS=false для API/worker. Пароль URL-кодировать.
   Для последующих миграций запускать одноразовый контейнер с DATABASE_URL владельца схемы;
   не передавать этот пароль рабочему процессу API. SQL рассчитан на имена из docker-compose.yml.
5. Создать отдельную disposable-базу islamcar_restore_check. Указать её URL только после проверки,
   что она не содержит нужных данных: восстановление использует --clean и стирает её содержимое.
6. Хранить копии вне сервера, ограничить права доступа к ним и выполнить полное восстановление
   в отдельную базу и временный каталог. Старые копии без files_sha256 не имеют проверки файлов.
7. Подключить реальные каналы уведомлений и платёжный магазин, затем проверить доставку и оплату.
   Ключи и пароли задаются в окружении, не в GitHub и не в сообщениях.
8. В GitHub включить защиту main с обязательным успешным CI и проверкой PR. Подключённый инструмент
   позволяет записывать код, но не менять branch protection; в рамках этого изменения она не включена.

## Границы проверки

Ни один аудит не доказывает отсутствие всех возможных уязвимостей. Парсер сканов не заменяет антивирус.
Регулярные выражения не гарантируют удаления любых ПД из свободного текста; сотрудник проверяет
предпросмотр, а передача во внешний ИИ по умолчанию выключена.

Очередь защищена от одновременного исполнения живыми workers, но доставка во внешний SMS/SMTP
сервис остаётся at-least-once: сбой после отправки и до фиксации результата может привести к повтору.
Абсолютное исключение повторов требует идемпотентности конкретного провайдера.

Юридические решения и утверждение шаблонов не заменены программными проверками.
Пагинация длинных реестров и более гибкие права документов — отдельные продуктовые доработки.
