# Демо-стенд в браузере (GitHub Codespaces)

GitHub Codespaces — временный компьютер в облаке GitHub, который запускается прямо со страницы репозитория.
В нём собирается и работает вся система: база данных, сервер API, фоновый обработчик, сайт для покупателей и
админка. GitHub выдаёт две ссылки, которые открываются на любом телефоне и компьютере.

Подходит, чтобы **показать систему вживую** на встрече: загрузить фото в админке и сразу увидеть его на сайте.
Не подходит для работы с реальными клиентами и для ссылок, которые должны работать несколько суток без перерыва
(см. «Ограничения»).

## Что в стенде

- Только тестовые данные: три демо-карточки автомобилей с пометкой «ДЕМО» и ненастоящими VIN.
- SMS и письма никому не отправляются — они записываются в журнал (`docker compose logs api worker`).
- Онлайн-оплата — тестовая, без денег. Распознавание по фото и помощник Claude выключены (нет ключа).
- Пароль базы и пароль владельца создаются случайно внутри Codespace. Файлы `.env`, `.demo/` и `demo-access.txt`
  не попадают в git.
- Не загружайте в стенд реальные документы и фотографии с персональными данными клиентов.

## Как запустить

1. Откройте https://github.com/8gsfsrnvp5-cell/Islam-Car и войдите в свой аккаунт GitHub.
2. Зелёная кнопка **Code** → вкладка **Codespaces** → **Create codespace on main**.
   Чтобы запустить другую ветку, сначала выберите её в списке веток слева вверху.
3. Откроется редактор в браузере. Внизу, в терминале, идёт запуск: первый раз 5–10 минут.
4. Когда всё готово, в терминале появятся:
   - ссылка на сайт для покупателей и ссылка на админку;
   - логин и пароль для входа в админку.

   То же записано в файле `demo-access.txt` слева в списке файлов. Показать снова — команда в терминале:

   ```bash
   bash .devcontainer/start-demo.sh --status
   ```

5. Скрипт сам открывает ссылки для всех. Если в итоге написано «Ссылки пока открываются только у вас»:
   внизу вкладка **Ports** → правой кнопкой по порту **3000** → **Port Visibility** → **Public**,
   то же для **3001**.

Проверить, что всё работает (вход, загрузка фото, фото на сайте без метаданных):

```bash
python3 .devcontainer/check-demo.py
```

### Свой логин и пароль (необязательно)

Если хотите заранее задать вход владельца сами, до создания Codespace добавьте два секрета:
https://github.com/settings/codespaces → **Codespaces secrets** → **New secret**:

- `ISLAMCAR_DEMO_LOGIN` — логин (например, адрес почты);
- `ISLAMCAR_DEMO_PASSWORD` — пароль не короче 10 символов.

В поле **Repository access** выберите `Islam-Car`. Секреты используются только при первом запуске Codespace.
Без них логин будет `owner@demo.local`, а пароль — случайный.

## Ограничения

- **Засыпает без работы.** Если в Codespace никто не работает, GitHub останавливает его — по умолчанию через
  30 минут. Срок можно увеличить до 4 часов: https://github.com/settings/codespaces → **Default idle timeout**.
  Пока Codespace остановлен, ссылки не открываются. Разбудить может только владелец аккаунта: откройте
  https://github.com/codespaces и нажмите на нужный Codespace. Ссылки и данные останутся прежними.
- **Бесплатное время ограничено.** На бесплатном личном аккаунте GitHub даёт 120 «ядро-часов» в месяц.
  Стенд использует машину с 2 ядрами, то есть примерно 60 часов работы в месяц. Остановленный Codespace
  время не тратит, но место на диске (бесплатно 15 ГБ в месяц) занимает.
- **Удаляется после долгого простоя.** Неиспользуемый Codespace по умолчанию удаляется через 30 дней вместе
  с данными стенда.
- **Ссылки длинные**, вида `https://имя-codespace-3000.app.github.dev`.
- Доступность Codespaces из России не гарантирована.

Для ссылок, которые должны работать круглосуточно, нужен арендованный сервер: та же сборка
(`docker compose up -d --build`) с обратным прокси HTTPS, см. [безопасность](security.md).

## Как остановить и удалить

https://github.com/codespaces → «…» справа от Codespace → **Stop codespace** (остановить, данные сохранятся)
или **Delete** (удалить вместе с данными стенда).

## Если что-то не работает

- Перезапустить сервисы и снова показать ссылки: `bash .devcontainer/start-demo.sh`
  (ничего не удаляет и не создаёт повторно).
- Журналы сервисов: `docker compose logs api`, `docker compose logs client`, `docker compose logs admin`.
- Состояние сервисов: `docker compose ps`.

Эта же сборка проверяется автоматически на GitHub при каждом изменении (задание «Docker — сборка и запуск
демо-стенда» в CI): запуск скрипта и `check-demo.py`.
